## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-04-01 | Spoofing / Elevation of Privilege | `sync-enqueue`, `sync-worker` left publicly invocable | high | mitigate | Both functions are deployed WITHOUT a `verify_jwt=false` override — Supabase's default `true` stays in force, so only the `pg_cron`/`pg_net` pipeline's authenticated call or an explicitly authorized manual invocation can trigger them |
| T-04-02 | Information Disclosure | `SUPABASE_SERVICE_ROLE_KEY` used inside both functions | high | mitigate | Catch/log statements in both handlers log only the RPC error or the popped message payload — never the service-role key or the Supabase client's config object |
| T-04-03 | Repudiation / Integrity | `pgmq_public.pop` deletes-on-read; a worker crash after popping but before finishing processing loses the message with no audit trail | medium | accept | Phase 1's message is a placeholder `{kind:"ping"}` with no business-critical payload; this risk is explicitly documented (see the task's `<reversibility>` note and the in-code comment) as something Phase 3's real sync worker must resolve by switching to `read`+`archive` for `SYNC-01`'s idempotency requirement — accepted only for this infra-proof phase |
| T-04-SC | Tampering | `@supabase/supabase-js@2.111.0` package | high | mitigate | Already verified Approved in 01-RESEARCH.md's Package Legitimacy Audit (22M+ weekly downloads, official `supabase/supabase-js` repo); version pinned in both functions' `deno.json` import maps |
