## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `pg_cron` (DB tier, inside Postgres) -> `pg_net` -> Edge Function (API tier) | Cron-originated HTTP call carrying credentials sourced from Vault |
| Executor's shell env -> `vault.create_secret()` calls | Secret values pass through process env only, never through a file |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-03-01 | Information Disclosure | `scripts/setup-vault-secrets.ts` execution | high | mitigate | Script reads secret values exclusively from `Deno.env.get()` at runtime; file itself is committed and contains zero literal values; execution never echoes the values to stdout/logs |
| T-03-02 | Tampering | `cron_sync_trigger` migration's `net.http_post` body | high | mitigate | URL and Authorization header are built exclusively from `vault.decrypted_secrets` lookups by name; the committed migration file contains no literal secret value (01-RESEARCH.md Pitfall 4) |
| T-03-03 | Spoofing | Future unauthorized direct invocation of `sync-enqueue` flooding the queue | medium | accept | `sync-enqueue`'s access control (keeping `verify_jwt` at its default `true`) is enforced when the function is built in plan 01-04; noted here since the queue capacity this migration creates is the DB-tier resource at risk |
